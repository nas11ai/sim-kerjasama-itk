# FE v2 — Irisan C1: Skema, Organisasi, Konfigurasi Umum — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Empat frame admin menjadi layar v2: `Scheme/IndexPage` + `Scheme/FormPage` (ADMIN-08-03/04), `SystemConfig/GeneralPage` (ADMIN-08-10, data acuan + channel notifikasi), `SystemConfig/OrganizationPage` (ADMIN-08-02, pohon unit + panel unit terpilih). Dua halaman legacy (`Schemes/IndexPage`, `Config/ReferenceEntitiesPage`) dihapus, dan enam lubang produksi yang ditemukan saat menulis rencana ditutup (W108, W109, W113, W114, W116, W117).

**Architecture:** Pola E1/E2. Controller tipis → FormRequest → Action beraudit (BR-RPT-09) → redirect; bacaan lewat `app/Queries/*` + `app/Data/View/*`. Satu definisi per angka penentu tombol: jumlah pengajuan aktif skema (`FormSubmission::active()`), jumlah pemakai data acuan (`ReferenceEntity::usageRelations()`), dan sensus subtree organisasi (`OrganizationCensus`). Angka-angka ini dipakai bersama oleh layar dan Action penegaknya (**Extract Method → Query**). Setiap task adalah irisan vertikal (route + controller + halaman + test), karena `ensure_pages_exist => true` dan `FrontendRouteNamesTest`.

**Tech Stack:** Laravel 13 / PHP 8.4, spatie/laravel-data, lorisleiva/laravel-actions, Inertia + Vue 3 `<script setup>` + TS, shadcn-vue, Pest, Vitest. Tanpa dependency baru.

**Spec:** `docs/design/fe-v2-design.md` §4.2–§4.5, baris C1 di §8, K1 di §9. Frame `../simpas-wireframe/screens/{ADMIN-08-02,ADMIN-08-03,ADMIN-08-04,ADMIN-08-10}/screen.js` + bagiannya di `docs/FRAME-AUDIT.md` / `docs/STATE-COVERAGE.md` (21 state). ## Review Focus

1. **Sunting skema lama menghapus aturannya.** Skema ber-`rules` `{min_reviewer_count: 3, legacy_key: "x"}` disunting namanya saja → kedua kunci tetap. Field aturan dikosongkan → hanya kunci itu yang hilang. → Task 2 `[SCH-RULE-17]` + `field aturan kosong membuang kuncinya saja`.
2. **Angka aturan sebagai teks.** Form mengirim `rules.min_reviewer_count = "3"` → tersimpan sebagai **int** 3 (pembacanya `is_int`), bukan string yang diam-diam diabaikan. `"tiga"`/`0`/`-1` → 422 pada field itu. → Task 2 `aturan angka tersimpan sebagai bilangan bulat` + `aturan bertipe ditolak bila bukan bilangan bulat positif`.
3. **Unit nonaktif di tengah subtree.** A → B (nonaktif, 2 profil): hapus A ditolak dan B tetap anak A. Memindah A ke bawah cucu C (A → B → C) ditolak. → Task 5 `[IAM-ORG-02] profil di bawah unit nonaktif tetap menghalangi` dan `[IAM-ORG-13] siklus lewat unit nonaktif ditolak`.
4. **Data lama bersiklus atau yatim.** Baris dengan `parent_id` yang membentuk lingkaran tetap tampil di pohon (sebagai akar) dan `OrganizationSubtree` berhenti. → Task 5 `pohon menampilkan unit bersiklus sebagai akar` + `subtree berhenti pada data bersiklus`.
5. **Pemegang `users.manage` tanpa `schemes.manage` (dan sebaliknya).** Ia melihat Organisasi tapi 403 di Skema/Konfigurasi, dan nav-nya sesuai. → Task 1, 3, 5 `wewenang`, `navigation.spec.ts`.
